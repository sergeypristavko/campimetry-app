# Алгоритмы тестирования

## Обзор стратегий

Приложение поддерживает две стратегии тестирования поля зрения:

| Стратегия | Презентации/точку | Время теста | Точность | Применение |
|-----------|-------------------|-------------|----------|------------|
| **Пороговая** | 4-8 | ~6-8 мин | Высокая (±1-2 dB) | Диагностика, мониторинг |
| **Надпороговая** | 1 | ~3 мин | Бинарная (виден/не виден) | Скрининг |

---

## Пороговая стратегия: Лестничный алгоритм (Staircase 4-2)

### Принцип работы

**Лестничный алгоритм** итеративно определяет минимальную яркость стимула, которую пациент может обнаружить в данной точке.

### Пошаговый алгоритм

```
1. Начальная интенсивность: 24 dB
   └─> Супрапороговое значение для большинства точек

2. Показать стимул
   └─> Если ВИДЕН → уменьшить яркость на 4 dB (сделать тусклее)
   └─> Если НЕ ВИДЕН → увеличить яркость на 4 dB (сделать ярче)

3. Детекция реверса (изменение направления)
   └─> Был виден → стал не виден (или наоборот)
   └─> Реверс №1: уменьшить шаг до 2 dB

4. Продолжить с шагом 2 dB
   └─> Реверс №2: завершить тестирование точки

5. Порог = среднее арифметическое интенсивностей в точках реверса
```

### Константы алгоритма

**Файл реализации:** `src/utils/algorithms.ts:9-16`

```typescript
const INITIAL_INTENSITY = 24;      // dB - начальная яркость
const LARGE_STEP = 4;              // dB - большой шаг
const SMALL_STEP = 2;              // dB - малый шаг (после 1-го реверса)
const REQUIRED_REVERSALS = 2;      // критерий завершения
const MAX_PRESENTATIONS = 10;      // страховка от бесконечного цикла
const MIN_INTENSITY = 0;           // dB - ярчайший стимул
const MAX_INTENSITY = 40;          // dB - тусклейший стимул
```

### Обоснование параметров

#### Начальная интенсивность: 24 dB

**Почему 24 dB?**
- Супрапороговое для большинства точек (норма 25-35 dB)
- Баланс: достаточно ярко для обнаружения, избегаем ceiling effect
- Humphrey стандарт: 25 dB [1]

#### Большой шаг: 4 dB

**Почему 4 dB?**
- Быстрая локализация порога
- 4 dB ≈ 2.5× изменение яркости (хорошо заметно)
- Компромисс скорость/точность [2]

**Обоснование:**
```
10^(4/10) ≈ 2.51 — изменение яркости в 2.5 раза
```

#### Малый шаг: 2 dB

**Почему 2 dB после реверса?**
- Нужна высокая точность вблизи порога
- 2 dB ≈ 1.58× изменение яркости (минимально различимая разница)
- Точность: ±1 dB
- Weber-Fechner закон: логарифмическое восприятие яркости [3]

**Обоснование:**
```
10^(2/10) ≈ 1.58 — изменение в 1.6 раза
```

#### Критерий завершения: 2 реверса

**Почему 2?**
- Баланс между временем и точностью
- Среднеквадратичное отклонение: ~1.5 dB [4]
- Альтернативы:
  - 1 реверс: быстрее, но ниже точность (~3 dB)
  - 3+ реверса: точнее, но утомление пациента

### Пример работы алгоритма

**Сценарий:** Реальный порог = 28 dB

```
Презентация | Интенсивность | Ответ | Действие | Шаг | Реверсы
------------|---------------|-------|----------|-----|--------
     1      |    24 dB      | Виден | ↓ -4 dB  | 4   | 0
     2      |    20 dB      | Не виден | ↑ +4 dB | 4 | 1 (реверс!)
     3      |    24 dB      | Виден | ↓ -2 dB  | 2   | 1
     4      |    26 dB      | Виден | ↓ -2 dB  | 2   | 1
     5      |    28 dB      | Виден | ↓ -2 dB  | 2   | 1
     6      |    30 dB      | Не виден | ↑ +2 dB | 2 | 2 (завершить!)

Порог = среднее(28, 30) = 29 dB
```

**Файл реализации:** `src/utils/algorithms.ts:42-93`

### Расчёт порога

**Метод 1: Среднее реверсов (основной)**
```typescript
// Найти точки реверса (изменение направления)
const reversalPoints = responses.filter((r, i) => {
  if (i === 0) return false;
  const prev = responses[i - 1];
  return (r.seen && !prev.seen) || (!r.seen && prev.seen);
});

// Усреднить интенсивности
threshold = mean(reversalPoints.map(r => r.intensity));
```

**Метод 2: Fallback (< 2 реверсов)**
```typescript
// Использовать последнюю интенсивность
threshold = responses[responses.length - 1].intensity;
```

## Надпороговая стратегия: Скрининг

### Принцип работы

**Надпороговая стратегия** показывает стимул **один раз** на яркости выше ожидаемого порога.

### Алгоритм

```
Для каждой точки:
  1. Получить нормальный порог для возраста и эксцентриситета
     └─> normalThreshold = getAgeNormalSensitivity(eccentricity, age)

  2. Добавить запас яркости (+6 dB)
     └─> intensity = normalThreshold + 6

  3. Показать стимул ОДИН РАЗ
     └─> Если ВИДЕН → норма ✅
     └─> Если НЕ ВИДЕН → вероятный дефект ⚠️

  4. Следующая точка (без итераций)
```

**Файл реализации:** `src/hooks/useTest.ts:254-272`

### Обоснование +6 dB

**Почему добавляем 6 dB к норме?**

1. **Внутрииндивидуальная вариабельность:** ±2-3 dB [5]
2. **Отвлечение внимания:** ~1-2 dB
3. **Моторная задержка:** ~1 dB
4. **Безопасный запас:** Минимизация ложноотрицательных

**Статистика:**
- Чувствительность скрининга: ~85% [6]
- Специфичность: ~80%
- NPV (negative predictive value): высокое для населения

### Преимущества

- ✅ **Быстро:** ~3 минуты (vs ~6 минут пороговой)
- ✅ **Просто:** Бинарный результат (норма/дефект)
- ✅ **Скрининг:** Подходит для массовых обследований
- ✅ **Мониторинг:** Отслеживание стабильных дефектов

### Недостатки

- ❌ **Нет количественной оценки** глубины дефекта
- ❌ **Ниже специфичность:** Больше ложноположительных
- ❌ **Не для диагностики:** Требуется подтверждение пороговым тестом

**Источники:**
- [5] Flammer J, et al. "Differential light threshold." Arch Ophthalmol. 1984;102(6):876-9.
- [6] Drance SM. "Early disturbances of chronic open-angle glaucoma." Ophthalmology. 1985;92(5):853-7.

## Продвинутые алгоритмы (не реализовано)

### SITA (Swedish Interactive Thresholding Algorithm)

**Принцип:**
- Байесовский подход с априорными вероятностями
- Предсказание порога на основе соседних точек
- Динамическая адаптация шага

**Преимущества:**
- ⏱️ На 50% быстрее стандартного Staircase
- 📊 Сравнимая точность
- 🎯 Интерполация пропущенных точек

**Ссылка:** Bengtsson B, Heijl A. "SITA Fast, a new rapid perimetric threshold test." Acta Ophthalmol Scand. 1998;76(4):431-7.

### ZEST (Zippy Estimation by Sequential Testing)

**Принцип:**
- Maximum-likelihood подход
- Обновление вероятностного распределения порога после каждого ответа
- Оптимизация следующего стимула

**Преимущества:**
- 🚀 Ещё быстрее SITA
- 📈 Высокая точность при малом числе презентаций

**Ссылка:** Turpin A, et al. "Properties of perimetric threshold estimates from full threshold, ZEST, and SITA-like strategies." Invest Ophthalmol Vis Sci. 2003;44(11):4787-95.

## Интенсивность в Opacity

### Формула преобразования

Децибелы не могут напрямую использоваться в CSS. Преобразуем в `opacity` (0-1):

```typescript
function intensityToOpacity(intensityDb: number): number {
  const minDb = 0;           // Ярчайший стимул
  const maxDb = 40;          // Тусклейший стимул
  const minOpacity = 0.08;   // Минимальная видимость (40 dB)
  const maxOpacity = 1.0;    // Максимальная видимость (0 dB)

  // Линейная интерполяция
  const normalized = intensityDb / maxDb;
  return maxOpacity - normalized * (maxOpacity - minOpacity);
}
```

**Примеры:**
```
0 dB   → opacity 1.0   (полностью непрозрачный)
24 dB  → opacity 0.448 (начальная интенсивность)
40 dB  → opacity 0.08  (почти прозрачный)
```

**Обоснование minOpacity = 0.08:**
- Ниже 0.08: стимул становится невидимым на большинстве мониторов
- Выше 0.08: недостаточный динамический диапазон

**Файл реализации:** `src/utils/algorithms.ts:168-174`

### Структура StaircaseState

```typescript
interface StaircaseState {
  pointId: string;                    // Идентификатор точки "x:y"

}
```
